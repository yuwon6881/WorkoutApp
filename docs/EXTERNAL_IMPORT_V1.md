# External import format, version 1

An authenticated endpoint supplies the provider-neutral prompt, and the import screen accepts the resulting JSON alongside the existing PDF workflow. An external provider's output is untrusted. WorkoutApp does not compare it with the original document. The envelope is limited to 8 MiB of UTF-8 JSON; the server generates internal identifiers, matches exercise names against the catalog, and creates an editable import rather than a program.

The root object contains `version: 1` and `program`. A program has `name`, optional `sourceWeekDays` (1–14), a `days` array, and optional `alternativeGroups`. A day has a unique document-local `key`, `week`, `name`, `exercises`, and optional `focus`, `notes`, `block`, `phase`, `phaseWeek` (default 1), `isRestDay` (default false), and `sourceReference`. Days and exercises remain in the supplied order. Rest days have an empty exercise list.

An exercise has `sourceName`, `sets`, and optional `notes`, `sequenceGroup`, `substitutions`, `restSeconds`, `demoUrl`, `demoLinks`, `sourceReference`, and `uncertainty`. Give consecutive exercises in the same superset the same `sequenceGroup` label, in the intended order; a group must have at least two members. Use distinct labels for separate groups, even when the source repeats a label. Demonstration links use the existing approved-host policy; unsupported links cause a validation error. The existing two-substitution limit applies.

A set has optional `repMin`, `repMax`, `targetRpe`, `rir`, `restSeconds`, `tempo`, `loadText`, `notes`, `repsText`, `restText`, `warmup`, `sourceReference`, and `uncertainty`. Both numeric rep bounds must be present or both absent. A missing numeric target stays absent. `type` may be `normal`, `warmup`, `dropset`, `amrap`, `myoreps`, `partials`, `lengthenedPartials`, `integratedPartials`, or `pause`; non-warmup types are represented by the app's existing technique notes. AMRAP does not imply a failure target. RIR accepts numbers, ranges and a trailing plus within 0–10.

A source reference is `{"kind":"pdfPage","page":2}`, `{"kind":"sheetCell","sheet":"Plan","cell":"A1:B3"}`, `{"kind":"text","text":"Section 2"}`, or `{"kind":"none"}`. An uncertainty is `{"flag":true,"reason":"Check this value"}`; `reason` is optional and limited to 200 characters. The source reference and uncertainty are review-only and do not assert verification.

Each alternative group has a document-local `id`, `kind` (`program` or `week`) and at least two `members`. Each member has a unique `id` within its group, a `name`, a nonempty `dayKeys` list, and optional `description` and `uncertainty`. Keys connect members to days only; the server replaces group, member and day keys with internal IDs. A day can belong to only one member across all groups. Therefore nested or overlapping alternative groups cannot be represented in v1. Each member must contain its own explicit days. The combined draft is limited to 400 days, even when alternatives would individually be smaller.

The server rejects unknown fields to avoid silently discarding prescriptions. External internal-ID fields and `verified`/`checked` assertions are ignored. All program values remain subject to the current draft and saved-program limits; in particular an exercise requires at least one set, so an unknown set count cannot be represented without review. No source document is uploaded or independently checked here.
